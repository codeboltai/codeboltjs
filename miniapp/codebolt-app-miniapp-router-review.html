CodeBolt MiniApp Router Review

Review artifact for the codebolt.app MiniApp routing, catalog/install surface, auth handoff, sample capability cloud, and lead-react deploy changes.

Router deployed Sample cloud deployed Edge auth deployed Portal deployed sample-cloud is test-only

Executive Summary

This change introduces a Cloudflare Worker router for codebolt.app so one deployed MiniApp version can serve many install subdomains without exposing execution tokens to the browser.

The router resolves an install record from KV, performs app-domain auth when required, mints a scoped execution token through the sample capability cloud, injects that token only into the upstream server request, and proxies to the provider deployment such as Netlify.

Public Surface

codebolt.app handles health, app catalog, install, and auth paths. <installId>.codebolt.app handles installed MiniApps.

Auth Boundary

Browser gets a signed cb_app_session cookie. Browser never gets the MiniApp execution token.

Capability Boundary

sample-cloud provides test db, blob, and tasks capabilities until this moves into the real API.

Install Boundary

app:<appId> controls who can create installs. install:<installId> controls who can open one installed instance.

Runtime Flow

1. User Finds App https://codebolt.app/apps

The apex catalog reads published app:<appId> records and shows app detail/install pages.

2. User Installs App POST /apps/:appId/install

The router checks app install policy, creates a private install record, and redirects to the install subdomain.

3. Browser Opens Install https://leadreact.codebolt.app/

Cloudflare route invokes the MiniApp router Worker.

4. Router Resolves Install MINIAPP_INSTALLS: install:leadreact

The record gives upstream URL, capability URL, workspace, access mode, and app id.

5. Auth Runs If Needed access: authenticated/private

Unauthenticated users redirect through portal and edge-api login-code redemption.

6. Router Proxies x-codebolt-execution-token

The upstream MiniApp receives server-only execution headers and calls sample-cloud capabilities.

Browser
  -> codebolt.app/apps
  -> app detail -> install policy check -> install:<installId> created
  -> leadreact.codebolt.app
  -> codebolt-miniapp-router Worker
  -> MINIAPP_INSTALLS KV
  -> optional codebolt.app/auth/start -> portal.codebolt.ai/miniapp-auth -> edge-api login code -> codebolt.app/auth/callback
  -> sample-cloud /token
  -> lead-react.netlify.app
  -> sample-cloud /capabilities/db.list

Known Risks and Follow-Ups

  • sample-cloud is not production auth. It mints unsigned dev tokens and should be replaced by real CodeBolt capability execution tokens.
  • Install metadata is currently in KV. This is good for v1 testing, but production should move install ownership, sharing, and deployment metadata into the real API.
  • Same-zone routing needs discipline. The router should proxy provider deployments such as Netlify; avoid same-zone Worker route fetch loops.
  • Public share behavior is not fully modeled yet. The router has public and authenticated; a richer share principal can be added later.
  • Frontend error handling should still be hardened. The backend 500 is fixed, but React should not assume successful API shape after any failed fetch.
