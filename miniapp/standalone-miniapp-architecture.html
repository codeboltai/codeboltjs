Implemented design · 13 August 2026

One public URL, two MiniApp execution models.

The router keeps https://<installId>.codebolt.app stable. Its install record now chooses between a separately deployed platform Worker and a packaged MiniApp running inside the shared Cloudflare MiniApp Server.

1. Core decision

type: platformworker

Existing deployment model

A provider deploys a complete MiniApp runtime to Netlify, Cloudflare, Deno, or another platform. The router proxies the public install URL to upstreamUrl and can mint a CodeBolt execution token through capabilityUrl.

type: miniappbundle

New shared-server model

The application is uploaded once as an immutable .miniapp package. The shared MiniApp Server creates an instance, loads its modules through Worker Loader, and runs its facet without deploying another top-level Worker.

The MiniApp package does not contain its own server control plane. Upload, start, stop, update, delete, storage allocation, limits, and dynamic execution are responsibilities of the one-time-deployed MiniApp Server.

R2

Stores content-addressed, immutable .miniapp files at packages/<sha256>.miniapp.

Supervisor DO

One deterministic supervisor per scope. It stores instance metadata and owns dynamic facets.

Storage DO

One deterministic storage namespace per scopeId:instanceId, separate from code execution.

Worker Loader

Builds a dynamic Worker from package modules plus a server-owned wrapper and applies server-owned limits.

3. The .miniapp package

The package is a single deterministic binary file. Consumers do not unzip a directory beside it. The format library reads the manifest and indexed payloads directly and verifies integrity before installation.

LayerPurpose
Magic + format versionRejects unrelated files and unsupported container revisions.
Canonical headerContains manifest metadata and the ordered file index.
Payload bytesStores runtime modules and public assets with deterministic offsets.
SHA-256 digestBecomes the package ID and detects byte-level modification.
hello-miniapp/
├─ miniapp.json               # codebolt.miniapp.v1 manifest
├─ modules/main.mjs           # application fetch handler
└─ public/index.html          # browser UI

miniapp pack hello-miniapp --output hello-miniapp.miniapp
miniapp verify hello-miniapp.miniapp
miniapp upload hello-miniapp.miniapp --server <server-url>

The manifest declares the application ID and version, runtime main module, Cloudflare compatibility date/flags, optional UI entry, and any package-level metadata. It does not choose a Durable Object ID or hold infrastructure credentials.

4. MiniApp Server responsibilities

Registry: accept and validate a package, compute its content address, and persist it to R2.
Supervisor: map a scope to a Durable Object and persist instance records such as package revision and lifecycle status.
Loader: read package modules, add the trusted runtime wrapper, set bindings and limits, and construct the dynamic Worker.
Facet: obtain a stable instance facet owned by the supervisor and dispatch the request to it.
Storage bridge: expose only the server-controlled storage API backed by the instance's Storage DO.

5. Typed routing records

The public hostname continues to identify an install. The resolved install record now contains an explicit route type. Legacy records without a type normalize to platformworker.

Why the direct server URL is not the product URL: the Worker address is an internal execution endpoint. Publishing its bearer token in browser JavaScript would expose package management and every instance. The router provides normal browser accessibility while keeping the management plane private.

6. Lifecycle flows

Package publication

Build creates a deterministic .miniapp.
CLI uploads raw bytes to the MiniApp Server.
Server validates the archive and stores it in R2 under its SHA-256 package ID.
Registry/deployment metadata records type: miniappbundle and that package ID.

User installation

Router authenticates the user and allocates the public install ID.
Install metadata is created with its type, scope, instance and package target.
For miniappbundle, the router calls the server to create the instance. If it already exists with another package, it updates the revision.
Browser is redirected to https://<installId>.codebolt.app.

Browser request

Router resolves install ID from the subdomain and checks public/authenticated/private access.
It strips browser cookies and authorization headers before the internal hop.
The record type selects either the platform upstream or MiniApp Server run route.
The MiniApp Server loads the current package revision, serves a public asset directly or dispatches to the instance facet.

Updating a package changes the instance revision and aborts the old facet, but it does not move or discard the Storage DO. Deleting an instance removes its facet, metadata, and storage deliberately.

8. Security boundaries

Browser boundary

The browser sees only the install domain. Router session cookies are removed before proxying.

Service boundary

MINIAPP_BUNDLE_SERVER_TOKEN exists only on the router and matches MINIAPP_SERVER_TOKEN on the server.

Runtime boundary

The server supplies bindings, outbound policy and CPU/subrequest limits; the package cannot define them.

Not yet a full trust sandbox

The prototype needs production policy for allowed compatibility flags, package signing, quotas, observability and abuse handling.

9. Local execution

The format and app contract are Cloudflare-independent. The current cloud server uses Worker Loader and facets; a local server can use the same package parser, manifest and request contract while substituting a Node or workerd execution adapter and a local storage adapter.

standalonetests/
├─ packages/miniapp-format/       package writer, parser and verifier
├─ packages/miniapp-cli/          pack, inspect, verify and upload commands
├─ apps/hello-miniapp/            minimal framework-free example
├─ apps/miniapp-server/           one-time Cloudflare control/execution plane
└─ tests/                          format, lifecycle and Wrangler integration

packages/miniapp-router-worker/   public hostname, auth and typed proxy

# Public application URL shape

The router configuration contains the default MiniApp Server URL. An individual record can override miniappServerUrl for migration or multi-region routing, but keeping a default avoids duplicating infrastructure URLs in every install.
